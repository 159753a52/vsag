## 结论先说

当前分支 `xlc/vsag-pr1-logic-only` 的提交为 `de80d6f8`，已在 ECS `root@122.9.41.164` 上完整编译通过。当前版本相对 baseline 在五个数据集上完成了 1、2、4、8、16、32 并发的成对 A/B 测试；每个模式每个并发档位执行 3 轮，每轮 10000 个查询，所有运行 `errors=0`，召回率没有变化。

按任务书“c8/c16/c32 三档都至少提升 15%”的严格口径：30 个目标组合中 22 个达到门槛。SIFT、MNIST、Fashion-MNIST 的 mutable/immutable 两种模式全部达标；NYTimes 和 GloVe-25 的部分档位未达标。因此不能把本次结果表述为“五个数据集全部达到 15%”。

主要收益来自 HGraph 搜索读路径的并发开销降低，尤其是全局读锁/写者排空机制和邻居访问预取；候选堆、VisitedList、参数缓存和 SIMD Batch4 是次要或数据集相关收益。消融结果显示，不能把全部收益归因给 SIMD Batch4。

## 具体做了哪些性能优化

### 1. 全局读路径和 immutable 快路

`BiasedRwLock` 给读者分配轻量 slot；没有 writer 等待时，读操作只增加 slot 计数，不进入传统 `shared_mutex` 的慢路径。writer 先阻止新读者，再等待已有 slot 清零，之后执行扩容、Tune、Remove、SetImmutable 等写操作。

`GlobalReadGuard` 用 RAII 管理这段读许可，处理同一线程的嵌套读和读许可转移。图索引确定为 immutable 后，搜索不再获取每个节点的邻居锁，从而减少搜索热路径上的锁分派。

这是本次消融中最大的收益来源。代价是锁实现更复杂，必须保证 writer pending、读许可释放和写者 drain 的顺序，否则会出现死锁或读写竞态。HGraph 并发、immutable Build/Add/Update 和多 writer 测试已覆盖这部分。

### 2. 邻居访问预取

`GraphDataCell::Prefetch` 从“只预取一个地址”改为预取当前邻居列表剩余字节；`MemoryBlockIO::PrefetchImpl` 按 block 边界分段，避免跨 block 越界。这样图遍历要读取后续邻居 ID 时，更可能已经在 cache 中。

profiling 中预取函数仍然是热点，说明它减少了等待但自身也占用 CPU；因此它的收益需要按数据集和邻居列表宽度复验。

### 3. VisitedList 单次 TestSet 和 touched words

旧路径先 `Get` 再 `Set`，同一个邻居要读两次位图。新路径用 `TestSet` 在一次操作中判断并标记访问；同时记录本轮真正写过的 word，Reset 只清这些 word，不再扫描整张位图。

这保持了“本次搜索是否访问过”的语义，不需要保留上轮具体节点；测试覆盖了边界 ID、重复设置、随机差分和多轮 reset。

### 4. 查询堆和容量

`BasicSearcher` 的 candidate heap 改为查询栈对象，返回的 top heap 仍由 `shared_ptr` 管理；常见 `ef` 下的 top heap 预留容量，减少 vector 扩容和搬移。候选堆操作使用具体 `StandardHeap` 类型，减少热路径虚函数分派。

消融显示这几项单独通常只贡献几个百分点，属于低风险叠加优化，而不是 15% 目标的唯一来源。

### 5. 参数和统计信息

thread-local JSON cache 让同一线程重复使用相同搜索参数的解析结果；LazyStatistics 将统计 JSON 的构造推迟到调用方真正读取结果时。普通业务如果不读取统计信息，可以避免不必要的 JSON 分配；本次 evaluator 为收集统计而读取它，所以 profiling 中统计序列化仍可见，不能把它当作本次 QPS 主收益。

### 6. SQ8 Batch4 SIMD

对一个 query 和四个不连续 code，新增四路内积 kernel，共享 query 加载，并保留 L2/IP/Cosine 的换算。它是功能上的 SIMD 优化，但 SIFT 消融显示独立收益很小且有噪声；后续若要保留，应在更多维度、量化类型和 CPU 上重新验证。
